# 实验结果与性能基线

## 1. 当前最重要的基线

当前可以作为系统级主锚点的结果是 `prototype_gate_chain_verify_2026-03-28` 下的 `full_pipeline_group2_ref`，它代表“真实可跑、可解释、可比较”的 pipeline 结果。
当前主锚点对应的 canonical 入口已启用 SmolLM semantic verifier 作为 Gate 的二次兜底。

关键指标如下：

- `macro_f1 = 0.801317`
- `known_acc = 0.784793`
- `oos_f1 = 0.901434`
- `gate_oos_rej = 0.908923`
- `gate_id_recall = 0.844375`

这组结果说明：系统已经能工作，但 Gate 仍然是主要权衡点。

## 2. 与无 Gate 方案相比

同一组消融里，两种无 Gate 方案明显更差：

- `no_gate_confidence`
  - `macro_f1 = 0.572482`
  - `oos_f1 = 0.236743`
- `no_gate_random`
  - `macro_f1 = 0.407990`

这说明 Gate 不是“可有可无的装饰模块”，而是系统成立的核心条件。

## 3. Gate scoring 与 decision policy 的现象

已验证的结论是：

- `weak_gate` 能工作，但不如当前主锚点。
- `mid_gate` 较弱，说明简单 top-k 平均并不必然更好。
- `strong_gate` 出现灾难性失效，属于需要避免的失败模式。
- `decision_threshold` 在已有结果中优于其他 decision 变体，且接近或略高于基线。

这意味着后续工作应该聚焦于“如何稳住 Gate 决策”，而不是盲目增加更复杂的融合结构。

## 4. 单点模型基线

### Router

`outputs/experiments/components/router/router_v19/results.json` 显示：

- `test_acc = 0.951979`
- `best_val_acc = 0.972667`
- 各 domain accuracy 约在 `0.9042 ~ 0.9750` 之间

Router 单点能力已经较强，因此不是当前主要瓶颈。

### Expert

`outputs/experiments/components/experts/experts_v19/all_results.json` 显示：

- 10 个 domain 的平均 `test_acc = 0.935593`
- 最低约 `0.870813`
- 最高约 `0.976190`

这说明 Expert 也不是当前系统瓶颈的主体。

## 5. 数据与难度结论

从审计和 OOS 分层结果看：

- tokenization 截断率为 0。
- OOS 中只有 9.6% 属于 Soft-Near。
- 大多数 OOS 是 Far-OOD，容易识别。

因此，项目后续真正要验证的是：如何把边界样本处理好，而不是继续怀疑整个数据集是否可用。

## 6. 当前主结论

1. Gate 是系统必要组件。
2. Router 和 Expert 单点能力已足够，不是主瓶颈。
3. 主要收益来自门控策略和级联决策策略。
4. 任何新实验都应该以 `full_pipeline_group2_ref` 为锚点做 delta，而不是拿单点模型做主结论。
5. 下一步更合理的消融，是把 `full_pipeline_group2_ref` 和 `no_gate_confidence`、`single_stage_minilm`、`single_stage_smollm`、`cascade_minilm` 放到同一协议里比较，而不是继续扩展 gate family。
