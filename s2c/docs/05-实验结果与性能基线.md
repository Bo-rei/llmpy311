# 实验结果与性能基线

## 1. 当前最重要的基线

当前可以作为系统级主锚点的结果是 `prototype_gate_chain_verify_2026-03-28` 下的 `full_pipeline_group2_ref`，它代表“真实可跑、可解释、可比较”的 pipeline 结果。
当前主锚点对应的 canonical 入口已启用 SmolLM semantic verifier 作为 Gate 的二次兜底。

关键指标如下：

- `macro_f1 = 0.801317`
- `known_acc = 0.784793`
- `oos_f1 = 0.901434`
- `gate_oos_rej = 0.908923`
- `gate_id_recall = 0.844375`

这组结果说明：系统已经能工作，但 Gate 仍然是主要权衡点。

## 2. 与无 Gate 方案相比

同一组消融里，两种无 Gate 方案明显更差：

- `no_gate_confidence`
  - `macro_f1 = 0.572482`
  - `oos_f1 = 0.236743`
- `no_gate_random`
  - `macro_f1 = 0.407990`

这说明 Gate 不是“可有可无的装饰模块”，而是系统成立的核心条件。

## 3. Gate scoring 与 decision policy 的现象

已验证的结论是：

- `weak_gate` 能工作，但不如当前主锚点。
- `mid_gate` 较弱，说明简单 top-k 平均并不必然更好。
- `strong_gate` 出现灾难性失效，属于需要避免的失败模式。
- `decision_threshold` 在已有结果中优于其他 decision 变体，且接近或略高于基线。

这意味着后续工作应该聚焦于“如何稳住 Gate 决策”，而不是盲目增加更复杂的融合结构。

## 4. 单点模型基线

### Router

`outputs/experiments/components/router/router_v19/results.json` 显示：

- `test_acc = 0.951979`
- `best_val_acc = 0.972667`
- 各 domain accuracy 约在 `0.9042 ~ 0.9750` 之间

Router 单点能力已经较强，因此不是当前主要瓶颈。

### Expert

`outputs/experiments/components/experts/experts_v19/all_results.json` 显示：

- 10 个 domain 的平均 `test_acc = 0.935593`
- 最低约 `0.870813`
- 最高约 `0.976190`

这说明 Expert 也不是当前系统瓶颈的主体。

## 5. 数据与难度结论

从审计和 OOS 分层结果看：

- tokenization 截断率为 0。
- OOS 中只有 9.6% 属于 Soft-Near。
- 大多数 OOS 是 Far-OOD，容易识别。

因此，项目后续真正要验证的是：如何把边界样本处理好，而不是继续怀疑整个数据集是否可用。

## 6. 当前主结论

1. Gate 是系统必要组件。
2. Router 和 Expert 单点能力已足够，不是主瓶颈。
3. 主要收益来自门控策略和级联决策策略。
4. 任何新实验都应该以 `full_pipeline_group2_ref` 为锚点做 delta，而不是拿单点模型做主结论。
5. 下一步更合理的消融，是把 `full_pipeline_group2_ref` 和 `no_gate_confidence`、`single_stage_minilm`、`single_stage_smollm`、`cascade_minilm` 放到同一协议里比较，而不是继续扩展 gate family。

## 7. 结果解读规范

- 不允许只报单一指标。
- 不允许跨协议、跨数据版本直接比较得出主结论。
- 所有表格必须附输出文件路径，保证可回放。

## 8. MiniLM 多簇/OOS 补充实验（v19）

新实验与上述系统级主锚点分属不同层级：它只比较 Gate 的 Known/OOS 判别，不将 Gate-only 指标写成端到端 intent accuracy。

已完成 `3 datasets × 3 KIR × 5 K × 2 distances × 3 seeds` 的
fixed-boundary 和 validation-tuned 网格，每个网格均为 270 个单元，
另有 KIR50/seed42 的 6 个 `K=8` stress control。当前证据不支持
“更多子中心总是更好”：

- CLINC150 的 fixed Euclidean 均值从 `K=1: 0.8681` 提升到 `K=2: 0.8740`，但继续增大 K 后回落。
- BANKING77-OOS 在 fixed 设置下对更大 K 更友好，对角马氏从 `K=1: 0.8665` 增至 `K=5: 0.8997`。
- StackOverflow 的 fixed Euclidean 从 `K=1: 0.7788` 降至 `K=2: 0.6453`，表明过度碎片化会显著破坏可分性。

受控 Gate-only Baseline 已完成 135/135 个单元。在三个 KIR 上对
OOS F1 求均值后：

- CLINC150 中 Entropy 最高（`0.9042`）；
- BANKING77-OOS 中 kNN 最高（`0.8750`）；
- StackOverflow 中 Energy 最高（`0.7961`）。

这些结果表明：多簇几何边界是数据集依赖的建模选择，不能声称其
普遍优于分类置信度或局部邻域方法。

### 8.1 多簇稳定性与 near-OOS

- `K=2` 的每意图 bootstrap ARI 中位数在 BANKING77-OOS、CLINC150、
  StackOverflow 上分别为 `0.9027`、`0.9201`、`0.8865`；`K=5` 降至
  `0.6975`、`0.6191`、`0.5350`。
- near-OOS 的平均 F1 仅为 `0.3399/0.4864/0.3531`，明显低于 far-OOS
  的 `0.9492/0.8252/0.6999`（顺序同上），近邻 OOS 是当前主要失败区域。
- 多模态分数与 `K=1 -> K=2` 收益的 Spearman 相关整体较弱，绝大多数
  bootstrap 95% CI 跨过 0。因此“簇更稳定”不能单独充当“增加 K 必然有益”
  的依据。

### 8.2 MiniLM 表征几何

- L2 归一化后，Euclidean 与 cosine 的最近意图完全一致，二者是 sanity
  check，不是两种独立距离创新。
- 去除第一主成分对 BANKING77-OOS 和 CLINC150 有益，对 StackOverflow 有害，
  说明各向异性校正不具有普适收益。
- raw embedding norm-only 的 OOS F1 接近无效，不能替代语义距离或分类置信度。

### 8.3 审计入口

可审计汇总位于 `artifacts/s2c/outputs/experiments/cluster_separability_v19/`。
论文表格主入口为 `kir_k_fixed_mean_std.csv`、`kir_k_tuned_mean_std.csv`、
`selected_k_frequency.csv`、`gate_baseline_summary.csv`和 `analysis/near_far_oos_summary.csv`；
`missing_cells.json` 和 `data_protocol_audit.json` 用于复现验收。
