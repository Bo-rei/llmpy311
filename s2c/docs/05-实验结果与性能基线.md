## 1. 当前最重要的基线

当前可以作为系统级主锚点的结果是 `prototype_gate_chain_verify_2026-03-28` 下的 `full_pipeline_group2_ref`，它代表“真实可跑、可解释、可比较”的 pipeline 结果。
当前主锚点对应的 canonical 入口已启用 SmolLM semantic verifier 作为 Gate 的二次兜底。

关键指标如下：

- `macro_f1 = 0.801317`
- `known_acc = 0.784793`
- `oos_f1 = 0.901434`
- `gate_oos_rej = 0.908923`
- `gate_id_recall = 0.844375`

这组结果说明：系统已经能工作，但 Gate 仍然是主要权衡点。

## 2. 与无 Gate 方案相比

同一组消融里，两种无 Gate 方案明显更差：

- `no_gate_confidence`
  - `macro_f1 = 0.572482`
  - `oos_f1 = 0.236743`
- `no_gate_random`
  - `macro_f1 = 0.407990`

这说明 Gate 不是“可有可无的装饰模块”，而是系统成立的核心条件。

## 3. Gate scoring 与 decision policy 的现象

已验证的结论是：

- `weak_gate` 能工作，但不如当前主锚点。
- `mid_gate` 较弱，说明简单 top-k 平均并不必然更好。
- `strong_gate` 出现灾难性失效，属于需要避免的失败模式。
- `decision_threshold` 在已有结果中优于其他 decision 变体，且接近或略高于基线。

这意味着后续工作应该聚焦于“如何稳住 Gate 决策”，而不是盲目增加更复杂的融合结构。

## 4. 单点模型基线

### Router

`outputs/experiments/components/router/router_v19/results.json` 显示：

- `test_acc = 0.951979`
- `best_val_acc = 0.972667`
- 各 domain accuracy 约在 `0.9042 ~ 0.9750` 之间

Router 单点能力已经较强，因此不是当前主要瓶颈。

### Expert

`outputs/experiments/components/experts/experts_v19/all_results.json` 显示：

- 10 个 domain 的平均 `test_acc = 0.935593`
- 最低约 `0.870813`
- 最高约 `0.976190`

这说明 Expert 也不是当前系统瓶颈的主体。

## 5. 数据与难度结论

从审计和 OOS 分层结果看：

- tokenization 截断率为 0。
- OOS 中只有 9.6% 属于 Soft-Near。
- 大多数 OOS 是 Far-OOD，容易识别。

因此，项目后续真正要验证的是：如何把边界样本处理好，而不是继续怀疑整个数据集是否可用。

## 6. 当前主结论

1. Gate 是系统必要组件。
2. Router 和 Expert 单点能力已足够，不是主瓶颈。
3. 主要收益来自门控策略和级联决策策略。
4. 任何新实验都应该以 `full_pipeline_group2_ref` 为锚点做 delta，而不是拿单点模型做主结论。
5. 本轮论文补实验保持 Gate/OOS 层受控比较，不重训 Router/Expert，
   不继续扩展新 gate family。

## 8. MiniLM 多簇/OOS 补充实验（v19）

新实验与上述系统级主锚点分属不同层级：它只比较 Gate 的 Known/OOS 判别，不将 Gate-only 指标写成端到端 intent accuracy。

已完成 `3 datasets × 3 KIR × 5 K × 2 distances × 3 seeds` 的
fixed-boundary 和 validation-tuned 网格，每个网格均为 270 个单元，
另有 KIR50/seed42 的 6 个 `K=8` stress control。当前证据不支持
“更多子中心总是更好”：

- CLINC150 的 fixed Euclidean 均值从 `K=1: 0.8681` 提升到 `K=2: 0.8740`，但继续增大 K 后回落。
- BANKING77-OOS 在 fixed 设置下对更大 K 更友好，对角马氏从 `K=1: 0.8665` 增至 `K=5: 0.8997`。
- StackOverflow 的 fixed Euclidean 从 `K=1: 0.7788` 降至 `K=2: 0.6453`，表明过度碎片化会显著破坏可分性。

受控 Gate-only Baseline 已完成 135/135 个单元。在三个 KIR 上对
OOS F1 求均值后：

- CLINC150 中 Entropy 最高（`0.9042`）；
- BANKING77-OOS 中 kNN 最高（`0.8750`）；
- StackOverflow 中 Energy 最高（`0.7961`）。

这些结果表明：多簇几何边界是数据集依赖的建模选择，不能声称其
普遍优于分类置信度或局部邻域方法。

### 8.1 K 的配对效应与 Baseline 稳健性

所有比较都在相同 KIR/data-seed 单元内做配对差值，并对 9 个配对单元
bootstrap 95% CI：

- CLINC150 fixed-Euclidean 中，`K=2` 相对 `K=1` 的 OOS F1 平均增量为
  `+0.0058`，95% CI `[+0.0025,+0.0087]`，9 个单元中 8 个获益；`K=5`
  反而为 `-0.0110`。
- BANKING77-OOS 中收益集中在更大 K；diagonal-Mahalanobis `K=5` 的
  配对增量为 `+0.0332`，CI `[+0.0211,+0.0447]`，9/9 单元获益。
- StackOverflow 的所有 `K>1` 都退化；Euclidean `K=2` 增量为 `-0.1335`，
  CI `[-0.2008,-0.0860]`。
- 相对 validation-selected MultiSphere，CLINC150 的 Entropy 配对增量为
  `+0.0329` 且 9/9 单元获益；BANKING77-OOS 的 kNN 为 `+0.0069`，但
  CI 跨 0；StackOverflow 的 Energy 为 `+0.0018`，CI 也跨 0。

这些配对结果比单纯汇报均值更强：数据集与距离度量存在真实交互，
不存在一个跨数据集通用的最优 K。

### 8.2 多簇质量、稳定性与 near-OOS

- 全 fixed 网格已汇总 9,900 条 intent-level 聚类诊断。以最小簇比例
  `<0.10` 或 effective-K 小于 requested-K 定义碎片化，BANKING77-OOS 的
  平均比例从 `K=2: 0.078` 增至 `K=5: 0.785`，CLINC150 从 `0.000`
  增至 `0.621`。
- StackOverflow 在 `K=2` 时碎片化比例仍为 0，但 OOS F1 已显著下降。
  因此它的失败不能只归因于“小簇样本太少”，还包含语义切分与拒识边界
  不匹配。

- `K=2` 的每意图 bootstrap ARI 中位数在 BANKING77-OOS、CLINC150、
  StackOverflow 上分别为 `0.9027`、`0.9201`、`0.8865`；`K=5` 降至
  `0.6975`、`0.6191`、`0.5350`。
- near-OOS 的平均 F1 仅为 `0.3399/0.4864/0.3531`，明显低于 far-OOS
  的 `0.9492/0.8252/0.6999`（顺序同上），近邻 OOS 是当前主要失败区域。
- 多模态分数与 `K=1 -> K=2` 收益的 Spearman 相关整体较弱，绝大多数
  bootstrap 95% CI 跨过 0。因此“簇更稳定”不能单独充当“增加 K 必然有益”
  的依据。

### 8.3 MiniLM 表征几何

- L2 归一化后，Euclidean 与 cosine 的最近意图完全一致，二者是 sanity
  check，不是两种独立距离创新。
- 去除第一主成分对 BANKING77-OOS 和 CLINC150 有益，对 StackOverflow 有害，
  说明各向异性校正不具有普适收益。
- raw embedding norm-only 的 OOS F1 接近无效，不能替代语义距离或分类置信度。

## 10. v20 机制补充实验（冻结 v19）

v20 独立写入 `artifacts/s2c/outputs/experiments/cluster_separability_v20/`，不覆盖
v19。当前已完成：

- validation-selected K 的 validation/test 排序相关、selection accuracy、test regret 和相对 K=1 安全性；
- K=1/K=2/selected-K 与 MSP、Energy、Entropy、kNN、LOF 的 near-OOS 对比；
- 现有 scoring throughput、RSS 和 Gate 总运行时间的可用字段汇总；
- 保持每个 intent KMeans 簇大小多重集合的随机分簇对照（105 个单元，5 repeats/单元）。

随机分簇结果使用：

```text
delta_semantic = F1_KMeans - mean(F1_RandomPartition)
```

BANKING77-OOS 的 delta 为正，支持局部语义归属贡献；StackOverflow 的 delta 为负，
说明 KMeans 切分与 OOS 边界目标不一致，不能把多中心数量本身解释成普遍收益。

端到端 Gate 替换已建立 36 单元 preflight/command manifest，但当前 workspace 缺少
Router/Expert checkpoint，因此只记录 `blocked_missing_inputs`，不复制历史 eval 指标，
也不伪造 Gate→Router→Expert 传递结论。

另外已完成 18 个同表征自适应局部边界 Baseline 单元（Known train silhouette
选择每个 intent 的 K=1..5）。相对固定 K=2，该 Baseline 在 BANKING77-OOS
提升，但在 CLINC150 和 StackOverflow 下降，结果保存在 v20 的
`adaptive_boundary_summary.csv`，不作为新方法贡献。

## 11. v21：MiniLM 四个核心假设验证

最新稿中的 MiniLM 是多簇边界成立的前提，而不是普通特征提取器。v21 围绕
“冻结表示 → 意图邻域 → 语义子簇 → 局部边界 → Known/OOS 决策”建立独立产物，
根目录为 `artifacts/s2c/outputs/experiments/cluster_separability_v21/`。

### 已完成：不训练语义空间探针

覆盖 CLINC150、BANKING77-OOS、StackOverflow 的 KIR50 和 seed `{13,42,87}`，
共 9 个单元，包含 Purity@5/10/20、类内/类间距离、最近意图 margin、线性探针、
kNN 探针，以及 near-OOS 表示碰撞—边界过覆盖分解。

Known test Purity@10 均值为 CLINC150 `0.8993`、BANKING77-OOS `0.8506`、
StackOverflow `0.8168`；相对分离度为 `0.4709`、`0.3987`、`0.2227`。K=2
near-OOS 表示碰撞率为 `0.6820`、`0.9751`、`0.8881`，说明当前 near-OOS
瓶颈更接近表示层碰撞，而不是单纯的局部半径过大。

### 已完成：子簇语义 casebook

`minilm_cluster_casebook.csv` 导出各 intent 子簇的代表句、TF-IDF 关键词、簇间
词汇 JSD 和簇大小；`minilm_cluster_annotation_template.csv` 提供人工审计模板。
自动关键词只作诊断，人工评分字段保持为空，避免用 MiniLM 自身循环证明语义。

### 已完成：Frozen/CE/SupCon 表征对照首轮

已完成三个数据集 KIR50 seed42 的完整 split、1 epoch 正式单元，固定边界使用
`K∈{1,2,selected-K}`、局部 diagonal covariance、`mean+std` 半径和 threshold=1。
Frozen、known-intent CE、SupCon 分开保存 checkpoint、scores、manifest 和汇总表。
这轮用于验证协议与趋势，不替代多 seed、多 epoch 的论文主表。

### 明确阻断项

v19 cache 只含最终 384 维 SentenceTransformer embedding，没有 MiniLM layer2/4/6
hidden states，因此 `layer_preflight.json` 将层级分析标记为 blocked；不能用 final
embedding 冒充中间层。完整多 seed adaptation、人工标注和语义保持扰动仍是后续工作。
