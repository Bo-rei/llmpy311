# 运维与治理规范

## 1. 输出治理

- 新实验结果必须写入 workspace 的 `artifacts/s2c/outputs/experiments/`。
- 稳定可复用产物放 `artifacts/s2c/outputs/core/`。
- 汇总与迁移记录放 `artifacts/s2c/outputs/reports/`。
- s2c 仓库和 workspace 根目录都不直接放散落结果文件。

## 2. 计划治理

- 活跃计划放 `plan/` 根目录。
- 历史计划归档到 `plan/archive/<date>/`。
- 归档时只移动文档，不改动主流程代码路径。

## 3. 脚本治理

- `scripts/` 只保留活跃最小集合。
- 历史脚本放 `scripts/archive/`。
- 归档脚本恢复前必须补说明和回归记录。

## 4. 测试治理

- 至少保留结构规则测试与 CLI smoke 测试。
- 新模块需要补充单元测试，并逐步纳入 CI。
- 任何改动若会影响训练/评估 CLI，都应该优先补 smoke 测试。

## 5. 实验治理与可复现

- 每次实验必须记录 `exp_id`、配置、随机种子、输出路径。
- 基线冻结后，后续只做锚点对比，不替换口径。
- 关键结论需具备离线复算路径。
- 若实验使用阈值或验证集挑选策略，必须明确写出“只在 val 上拟合”。

## 6. 结论治理

- 只有能回放到输出文件的结论才允许进入主文档。
- 若某项结果尚在试验中，必须标记为“候选”或“未定”。
- 任何新的消融实验完成后，都要同步更新性能基线和当前状态文档。

## 7. 重构治理

- 结构整理优先做“说明收敛”，再做“路径迁移”。
- 任何目录重组都必须先保证 CLI 参数兼容，不影响既有实验复现。
- 如果历史脚本仍被引用，先补封装入口，再考虑归档或移动。
- Gate 的 semantic verifier 是二次兜底，不应替代主几何门控路径。
