# 训练与评估流程

## 1. 环境准备

执行目录: `s2c`

```bash
conda activate bo
python -m src.cli prepare --dataset clinc150 --kir 50
```

建议先确认数据和审计文件是否存在，再启动长任务。

## 1.1 原始数据放置约定

原始数据位于工作区的 `assets/datasets/s2c/source/`：

- `banking77_oos`
- `snips`

CLINC150 使用 `assets/datasets/s2c/source/clinc150/data`。派生数据位于
`assets/datasets/s2c/prepared/data/`，结果与检查点位于 `artifacts/s2c/`。

## 1.2 支持的入口

活跃工作流只通过下面的 source-module CLI 启动；本页保留的 `tools/` 命令是内部
实现和历史复现实验的参数参考，不是稳定公共接口。

```bash
python -m src.cli {prepare,train,evaluate,ablate} --dataset <dataset> --kir <25|50|75>
```

## 2. 分阶段训练

### 2.1 Gate 训练

```bash
python -m src.cli train --dataset clinc150 --kir 50
```

Gate 的作用是先决定是否拒识。当前主线不再只看单点 loss，而是看它对整个 pipeline 的影响。

如果你在多数据集 benchmark 上训练，建议显式传 `--data_root` 指向新重建产物，例如：

```bash
python tools/gate/train_multisphere_corrected.py \
  --data_root data/multidataset/v19/banking77_oos/kir50_seed42 \
  --output_dir outputs/experiments/multi_dataset_v19/banking77_oos/kir50_seed42/gate
```

### 2.1.1 Gate 后置 Prompt Verifier 训练

```bash
python tools/train/train_semantic_verifier_v19.py \
  --router_ckpt outputs/experiments/multi_dataset_v19/banking77_oos/kir50_seed42/router/best_model.pt \
  --router_train data/multidataset/v19/banking77_oos/kir50_seed42/router/train.json \
  --gate_train data/multidataset/v19/banking77_oos/kir50_seed42/gate/train.json \
  --gate_val data/multidataset/v19/banking77_oos/kir50_seed42/gate/val.json \
  --output_dir outputs/experiments/multi_dataset_v19/banking77_oos/kir50_seed42/prompt_verifier
```

这条入口用于训练 gate 专用的 decoder-only prompt verifier，保持 `prototype top-k -> rerank -> threshold/fusion` 的后置验证链路。

### 2.2 Router 训练

```bash
python tools/train/train_router_v19.py \
  --data_dir data/multidataset/v19/banking77_oos/kir50_seed42/router \
  --output_dir outputs/experiments/multi_dataset_v19/banking77_oos/kir50_seed42/router
```

Router 负责 domain 预测。它的单点能力已经不错，但系统级误差主要不在这里。

### 2.3 Expert 训练

按域或批量入口执行专家训练（以当前 `tools/train` 中实现为准）。

当前专家训练已经有现成产物可参考，默认评估结论应以 `outputs/experiments/components/experts/experts_v19/` 的结果为准。

## 3. 系统级评估（v19）

```bash
python tools/eval/eval_system_pipeline_v19.py \
  --data_root data/multidataset/v19/banking77_oos/kir50_seed42 \
  --data_root_scope all \
  --gate_detector_path outputs/experiments/multi_dataset_v19/banking77_oos/kir50_seed42/gate/corrected_multisphere_detector.json \
  --router_ckpt outputs/experiments/multi_dataset_v19/banking77_oos/kir50_seed42/router/best_model.pt \
  --experts_root outputs/experiments/multi_dataset_v19/banking77_oos/kir50_seed42/experts \
  --prompt_semantic_verifier_ckpt outputs/experiments/multi_dataset_v19/banking77_oos/kir50_seed42/prompt_verifier/best_model.pt \
  --output_dir outputs/experiments/multi_dataset_v19/banking77_oos/kir50_seed42/eval \
  --batch_size 64 \
  --semantic_gate_enabled \
  --semantic_gate_mode prototype \
  --semantic_gate_threshold 0.85
```

评估时主指标统一为以下 6 项，且都以**整个级联 pipeline 最终输出**为准：

- `overall_accuracy`
- `known_accuracy`
- `oos_accuracy`
- `macro_f1`
- `known_macro_f1`
- `oos_f1`

其中：

- `known_accuracy` 与历史字段 `known_intent_accuracy` 数值等价，但命名更明确
- `oos_accuracy` 与历史字段 `gate_oos_rejection` 数值等价，但统一到 accuracy 口径
- `known_macro_f1` 只在已知 intent 集合上做 macro average，不包含 `OOS`

以下指标降级为辅助诊断，不作为主表第一屏：

- `gate_id_recall`
- `gate_oos_rejection`
- `known_intent_accuracy`
- `intent_acc_given_gate_pass`
- `domain_accuracy`
- `domain_acc_given_gate_pass`
- `open_set_metrics`
- `calibration`
- `intent_diagnostics`
- `oos_by_source`

### 3.1 多数据集重建

统一重建所有数据集与 KIR 组合：

```bash
python scripts/data/active/rebuild_multi_dataset_v19.py \
  --datasets CLINC150 BANKING77-OOS SNIPS \
  --kir_values 0.25 0.5 0.75 \
  --output_root data/multidataset/v19
```

如果只想先生成单个组合，也可以单独传 `--datasets` 和单个 `--kir_values`。

### 3.1.1 冻结 Prototype 基线复现

如果要复现历史最优 Prototype Gate，请使用冻结入口，而不是最终展示版 wrapper：

```bash
python tools/analysis/run_prototype_gate_frozen_baseline_v19.py \
  --data_root data/v19 \
  --output_dir outputs/experiments/pipeline/frozen_prototype_gate/prototype_gate_frozen_2026-04-09/prototype_gate_pipeline_frozen
```

冻结版默认对齐历史最优配置：

- `gate_mode=multi_prototype`
- `semantic_gate_mode=prototype`
- `semantic_gate_threshold=0.85`
- `semantic_uncertain_low=0.98`
- `semantic_uncertain_high=1.05`
- `prototype_centers_default=1`
- `multi_proto_id_threshold=0.5904965996742249`

### 3.2 多数据集编排

在 checkpoint 已经准备好的前提下，可以用统一入口批量跑 rebuild + eval：

```bash
python tools/analysis/run_multi_dataset_benchmark_v19.py \
  --datasets CLINC150 BANKING77-OOS SNIPS \
  --kir_values 0.25 0.5 0.75 \
  --artifact_root outputs/experiments/multi_dataset_v19 \
  --data_root_base data/multidataset/v19
```

当前默认会使用历史最优方法族的 Gate 语义判别配置：

- `semantic_gate_mode=prototype`
- `semantic_gate_threshold=0.85`
- `prototype_centers_default=1`
- `semantic_uncertain_low=0.98`
- `semantic_uncertain_high=1.05`

### 3.3 多数据集训练（统一 Gate 为历史最优方法族）

训练入口 `run_multi_dataset_training_v19.py` 现在默认 `--gate_profile historical_best`，
对应 Gate 训练参数族为：

- `center_mode=class_centroid_mixture`
- `distance_metric=mahalanobis_diag`
- `l2_normalize=true`
- `subcenters_per_intent=2`
- `gate_min_id_recall=0.80`（profile-aware 默认，避免过严约束导致 OOS 拒识退化）

示例：

```bash
python tools/analysis/run_multi_dataset_training_v19.py \
  --datasets CLINC150 BANKING77-OOS SNIPS \
  --kir_values 0.25 0.5 0.75 \
  --seed 42 \
  --resume \
  --device cuda
```

## 4. 消融实验

### 4.1 MiniLM 多簇与 OOS 可分性实验

本轮补充实验使用独立输出根目录，不覆盖历史 `paper_results`：

```bash
# 协议最小闭环
python -m tools.experiments.cluster_separability grid \
  --phase smoke --dataset clinc150 --kir 50 --data-seed 42 \
  --k-gate 2 --distance mahalanobis_diag

# 270 单元固定边界主消融；可中断后恢复
python -m tools.experiments.cluster_separability grid \
  --phase fixed --grid --resume

# 运行前只审计输入矩阵
python -m tools.experiments.cluster_separability grid \
  --phase fixed --grid --dry-run

# 受控 MiniLM Gate-only Baseline（支持断点续跑）
python -m tools.experiments.cluster_separability baseline --grid --resume

# 稳定性与 selected-K 的 near/far、overlap、表征控制
python -m tools.experiments.cluster_separability analyze --study all --skip-nonlinear

# 汇总论文表格与缺失单元审计
python -m tools.experiments.cluster_separability export \
  --root ../artifacts/s2c/outputs/experiments/cluster_separability_v19
```

固定边界只改变每个 intent 的子中心数 `K_gate`；tuned 阶段只使用 validation 选择半径和 margin。所有新指标以 OOS 为正类，历史 `DetectorMetrics.f1_like` 仅用于旧结果兼容。

TextOIR 位于工作区根目录的独立仓库 `../textoir`，通过 `tools/compat/textoir/` 以外部进程运行；其随机 known-label 协议与 s2c 主协议分表报告。

TextOIR 正式矩阵的可恢复入口为：

```bash
python -m tools.compat.textoir.run_textoir_matrix \
  --textoir-root ../textoir \
  --output-root ../artifacts/s2c/outputs/experiments/cluster_separability_v19/textoir_protocol/official_runs \
  --bert-model <local-bert-base-uncased-path> \
  --python-executable ../.venvs/textoir-llmpy311/bin/python \
  --datasets banking oos stackoverflow \
  --methods MSP DOC ADB \
  --known-cls-ratios 0.25 0.5 0.75 \
  --seeds 0 1 2 \
  --gpu-id 0 --timeout 7200 --resume
```

runner 对每个单元保留不可变 `attempt_XXXX`，只跳过已同时通过上游产物、
clone 清洁性和 s2c 指标重算审计的单元。OpenMax 在 Python 3.11 下因上游
`libMR.MR` ABI 不兼容而停在 preflight，不得用缺失预测的结果补表。

当前最合理的消融入口已经切换为结构必要性 + 异构骨干方案：

```bash
python tools/analysis/validate_router_confidence_threshold_v19.py \
  --gate_val data/v19/gate/val.json \
  --router_ckpt outputs/experiments/components/router/router_v19/best_model.pt \
  --experts_root outputs/experiments/components/experts/experts_v19 \
  --experts_data_root data/v19/experts \
  --output_dir outputs/experiments/pipeline/ablations/structure_backbone_v19/<exp_id>/00_threshold_validation

python tools/analysis/tune_semantic_gate_v19.py \
  --gate_val data/v19/gate/val.json \
  --prompt_semantic_verifier_ckpt outputs/prompt_semantic_verifier_v19/best_model.pt \
  --output_dir outputs/experiments/pipeline/semantic_gate_tuning/<exp_id>

python tools/analysis/run_structure_backbone_ablation_v19.py --exp_id <exp_id>
```

这套流程会自动生成：

- `full_pipeline_group2_ref`
- `no_gate_confidence`
- `single_stage_minilm`
- `single_stage_smollm`
- `cascade_minilm`
- 以及可选的 `no_gate_random` / `oracle_oos` 诊断项

旧的 `run_pipeline_ablation_matrix_v19.py` 已归档到 `tools/archive/code_cleanup_2026-03-28/analysis/`。
`run_known_intent_ratio_experiments_v19.py` 也已归档，不再作为主入口。

## 5. 评估输出检查

每次评估至少检查以下文件：

- `eval_results.json`
- `predictions.json`（若启用）
- 关键配置快照或 identity 文件

并确认结果落在 `outputs/experiments/` 下，同时保留对应的实验 ID。
