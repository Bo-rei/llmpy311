# 消融实验方案

## 1. 为什么要做这组消融

当前项目已经比较清楚地说明了两件事：

- Router 单点能力足够强。
- Expert 单点能力也足够强。
- 系统级损耗主要集中在 Gate 与级联边界。

所以后续消融不再继续扩展 gate family，也不再把 prototype / decision 作为主表，而是集中证明下面两个命题：

1. `Gate -> Router -> Expert` 这条三层结构是否必要。
2. `MiniLM` 做 Gate、`SmolLM` 做 Router/Expert 的异构骨干组合是否有价值。

## 2. 本次消融的主锚点

主锚点固定为当前可复现的完整系统：

- `full_pipeline_group2_ref`

当前基线指标仍以 [05-实验结果与性能基线.md](05-实验结果与性能基线.md) 为准。后续所有实验都只报告相对这个锚点的 delta。

## 3. 实验问题定义

### 问题 A: 三层结构是否必要

比较以下配置：

- `full_pipeline_group2_ref`
- `no_gate_confidence`
- `single_stage_minilm`
- `single_stage_smollm`

核心问题不是“谁单点更强”，而是“删掉 Gate 或删掉层次结构之后，系统是否还成立”。

### 问题 B: 异构骨干是否有价值

比较以下配置：

- `full_pipeline_group2_ref`
- `cascade_minilm`

核心问题是：在保持 `Gate -> Router -> Expert` 结构不变时，混合骨干是否优于纯 MiniLM 级联。当前 `single_stage_*` 只用于单阶段架构对照，不再作为 backbone 消融。

## 4. 推荐实验矩阵

### 4.1 结构必要性组

| 组别 | 说明 | 预期用途 |
|------|------|----------|
| `full_pipeline_group2_ref` | 完整三级结构 | 主锚点 |
| `no_gate_confidence` | 去掉 Gate，仅靠 Router confidence OOS | 证明 Gate 是否必要 |
| `single_stage_minilm` | MiniLM + LogisticRegression 单阶段控制 | flat 架构对照 |
| `single_stage_smollm` | 单阶段 SmolLM 控制 | flat 架构对照 |

### 4.2 骨干消融组

| 组别 | 说明 | 预期用途 |
|------|------|----------|
| `full_pipeline_group2_ref` | MiniLM Gate + SmolLM Router/Expert | Hybrid cascade 主锚点 |
| `cascade_minilm` | MiniLM Gate + MiniLM Router/Expert | 保持级联结构的纯 MiniLM 对照 |

### 4.3 诊断组

| 组别 | 说明 | 预期用途 |
|------|------|----------|
| `no_gate_random` | 去掉 Gate，随机门控 | 边界失败诊断 |
| `oracle_oos` | 使用真值 OOS 标签 | 上界参考 |

## 5. 运行协议

- 数据必须固定为 `data/current -> v19`。
- 所有阈值拟合只能在验证集上做。
- `no_gate_confidence` 的阈值必须来自 validation-only 搜索。
- `single_stage_minilm` 和 `single_stage_smollm` 必须使用同一套 OOS 策略口径。
- `cascade_minilm` 的 OOS 判断必须来自 Gate detector，不能使用单阶段 MSP 替代。
- 每组实验都必须保留 `eval_results.json`、`predictions.json`、`run_manifest.json`。

## 6. 推荐执行顺序

1. 先跑 validation-only 的 router confidence 阈值搜索。
2. 再跑 `full_pipeline_group2_ref`。
3. 再跑 `no_gate_confidence`。
4. 再跑 `single_stage_minilm`。
5. 再跑 `single_stage_smollm`。
6. 再跑 `cascade_minilm`。
7. 如需补边界说明，再跑 `no_gate_random` 和 `oracle_oos`。

## 7. 推荐命令

### 7.1 阈值验证

```bash
python tools/analysis/validate_router_confidence_threshold_v19.py \
  --gate_val data/v19/gate/val.json \
  --router_ckpt outputs/experiments/components/router/router_v19/best_model.pt \
  --experts_root outputs/experiments/components/experts/experts_v19 \
  --experts_data_root data/v19/experts \
  --output_dir outputs/experiments/pipeline/ablations/structure_backbone_v19/<exp_id>/00_threshold_validation
```

### 7.2 主跑器

```bash
python tools/analysis/run_structure_backbone_ablation_v19.py \
  --exp_id <exp_id>
```

## 8. 评价指标

每组实验至少报告：

- `macro_f1`
- `overall_accuracy`
- `known_intent_accuracy`
- `oos_f1`
- `gate_id_recall`
- `gate_oos_rejection`

如果要解释“结构是否必要”，重点看：

- `full_pipeline_group2_ref` vs `no_gate_confidence`
- `full_pipeline_group2_ref` vs `single_stage_minilm`
- `full_pipeline_group2_ref` vs `single_stage_smollm`

如果要解释“异构骨干是否有用”，重点看：

- `full_pipeline_group2_ref` vs `cascade_minilm`

## 9. 预期结论写法

结论建议只写两句：

1. 三层结构是否必要，取决于 `full_pipeline_group2_ref` 相对 `no_gate_confidence` 的稳定优势。
2. 混合 MiniLM + SmolLM 骨干是否有价值，取决于 `full_pipeline_group2_ref` 相对 `cascade_minilm` 的稳定优势。

不再把 gate family、prototype family、decision family 作为主表叙事。
