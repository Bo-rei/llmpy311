# 代码与目录结构

## 1. 根目录职责

- `src/`: 核心可导入代码，放可复用实现，不放一次性脚本。
- `tools/`: 训练、评估、分析入口，所有可执行实验都从这里发起。
- `scripts/`: 数据处理和辅助脚本，当前只保留仍有复用价值的活跃脚本。
- `data/`: 版本化数据集与 `current` 链接。
- `outputs/`: 模型产物、实验结果、汇总报告、迁移日志。
- `configs/`: 训练、路径、门控相关配置。
- `tests/`: 结构规则与集成 smoke 测试。
- `docs/`: 唯一文档体系。

当前治理重点：
- 训练与评估入口统一从 `tools/` 启动。
- 当前工作树没有 `tools/archive/`；历史复现信息保存在 `docs/historical_repro_bundle/` 与实验产物 manifest 中。
- 新增评估入口统一落在 `tools/eval/`。

## 2. 核心代码分层

- `src/gate/`: OOS 检测核心实现，包括几何门控、prototype gate、语义 verifier 等。
- `src/router/`: 域路由能力，负责从 ID 样本中选出目标 domain。
- `src/models/`: 模型封装和通用模块。
- `src/pipeline/`: 系统级串联推理逻辑，Gate/Router/Expert 在这里被组合成完整链路。
- `src/inference/`: 推理接口与服务层封装。
- `src/utils/`: 公共工具函数。

## 3. 常用工具入口

- `tools/gate/train_multisphere_corrected.py`: Gate 训练稳定入口。
- `tools/train/train_router_v19.py`: Router 训练稳定入口。
- `tools/train/train_expert_v19.py`: 单域 Expert 训练稳定入口。
- `tools/train/train_all_experts_v19.py`: 批量 Expert 训练稳定入口。
- `tools/eval/eval_system_pipeline_v19.py`: 系统级评估。
- `tools/eval/eval_single_model_ood_v19.py`: MiniLM flat baseline。
- `tools/eval/eval_flat_smolm_v19.py`: SmolLM flat baseline。
- `tools/analysis/validate_router_confidence_threshold_v19.py`: validation-only router threshold 搜索。
- `tools/analysis/run_structure_backbone_ablation_v19.py`: 新的结构必要性 + 异构骨干主跑器。
- `tools/analysis/run_multi_dataset_benchmark_v19.py`: 多数据集 benchmark 编排入口。
- `tools/analysis/run_multi_dataset_training_v19.py`: 多数据集多KIR训练主编排入口（gate/router/experts/verifier）。
- `tools/analysis/run_prototype_gate_frozen_baseline_v19.py`: 冻结历史 prototype 最优结果的复现实验入口。
- `tools/analysis/summarize_ablation_results_v19.py`: 主消融结果汇总。
- `tools/analysis/export_ablation_table_v19.py`: 论文表格导出。
- `tools/analysis/rerender_gate_score_distribution_v19.py`: Gate score 分布图重新渲染。
- `tools/train/train_semantic_verifier_v19.py`: gate prompt verifier LoRA 训练入口。
- `scripts/data/active/rebuild_multi_dataset_v19.py`: CLINC150 / BANKING77-OOS / SNIPS 统一重建入口。

## 4. data 目录

- `data/current`: 当前活跃数据入口，实际指向 `v19`。
- `data/v19/gate/`: Gate 数据。
- `data/v19/router/`: Router 数据。
- `data/v19/experts/`: 10 个专家域的数据。
- `data/multidataset/v19/<dataset_slug>/kirXX_seed42/`: 多数据集 benchmark 的重建产物。

多数据集输入约定（训练主编排器默认使用）：
- `dataset_slug ∈ {clinc150, banking77_oos, snips}`。
- `kirXX_seed42` 使用两位百分比标签：`kir25_seed42`、`kir50_seed42`、`kir75_seed42`。

## 5. outputs 目录

- `outputs/core/`: 长期稳定产物，例如 gate detector、模型与元数据。
- `outputs/experiments/`: 各类实验运行目录。
- `outputs/reports/`: 汇总报告、审计和迁移日志。

多数据集输出约定：
- 训练产物：`outputs/experiments/multi_dataset_v19/<dataset_slug>/<kirXX_seed42>/`。
- 阶段清单：`.../<stage>/stage_manifest.json`。
- 运行总清单：`.../train_manifest.json`。
- 汇总结果由各实验输出及其 manifest 追溯；不要假设所有实验共享固定的汇总目录。

治理要求：禁止将新实验结果直接写入 `outputs/` 根目录，必须进入对应子目录并保留配置快照。

## 6. 结构整理建议

- `tools/analysis/` 保持为主入口；历史复现通过文档和 manifest 追溯，不从虚构的归档路径启动。
- `scripts/data/active/` 只保留仍会复用的数据构建脚本，其余脚本归档。
- 新增或重命名 CLI 时，优先保持兼容旧参数，再逐步收敛为单一推荐入口。
- 如果要移动文件，先更新文档与 smoke 测试，再做路径迁移。

## 7. 当前 semantic gate 说明

- `run_prototype_gate_frozen_baseline_v19.py` 对齐历史最优 prototype 基线，冻结 `semantic_gate_mode=prototype` 与对应阈值。
- 当前完整流水线入口是 `tools/eval/eval_system_pipeline_v19.py`；它按配置决定是否启用 `semantic_gate_mode=llm_verifier` 作为 Gate 的二次兜底。
- 主线仍然先走几何 Gate，再对不确定样本做 SmolLM 语义复核。

## 8. 活跃脚本职责

- `audit_v19_2_data.py`: 结构审计与约束验证。
- `build_known_intents_ratio_splits_v19.py`: 已知意图比例生成。
- `rebuild_multi_dataset_v19.py`: 活跃的多数据集派生数据构建入口；旧分层构建脚本已归档。
- `rebuild_v19_2_strict.py`: 依据 known/unknown 配置重构 v19.2 数据。
