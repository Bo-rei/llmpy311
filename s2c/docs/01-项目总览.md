# 项目总览

## 1. 这个项目是什么

s2c 是一个面向开放意图识别的分层系统，核心链路为：

- Stage 0: Gate，负责把输入判定为已知意图（ID）还是未知意图（OOS）。
- Stage 1: Router，负责把通过 Gate 的 ID 样本路由到正确域。
- Stage 2: Expert，负责在对应域内做细粒度意图分类。

这个项目的重点不是单点分类器，而是一个真实的级联系统：先识别是否该拒识，再决定去哪一个域，最后再做域内分类。

## 2. 这个项目解决什么问题

开放意图识别的难点不在“会不会分类”，而在“遇到不属于训练集合的问题时，能不能先拒识”。
因此项目目标不是追求某个单一模型的最高 accuracy，而是同时平衡：

- OOS 拒识能力。
- 已知意图识别准确率。
- 端到端 Macro-F1。
- 推理链路是否可解释、可调试、可复现。

## 3. 当前技术路线

- Gate: MiniLM embedding + 几何判别，当前主线是 prototype / multi-sphere / score-based 相关方案。
- Router: SmolLM 轻量路由模型，使用 LoRA 微调。
- Expert: 按域拆分的 SmolLM 专家模型，每个域独立训练与评估。
- Pipeline: Gate -> Router -> Expert 串联评估，最终看系统级指标而不是单模型指标。

## 4. 当前仓库的真实状态

- 数据版本已经锁定到 `data/current -> v19`。
- 训练、评估、消融、归档的入口已经存在，并且都有对应输出目录。
- Router 和 Expert 都已经有可用产物，但项目瓶颈不是这两个组件本身，而是 Gate 以及 Gate 与后段的衔接策略。
- 当前最重要的工作是把已有结果解释清楚，把消融实验做成“能说明问题”的实验，而不是继续堆单点改动。

## 5. 已验证的工程事实

- 数据审计显示训练/测试没有文本重叠。
- tokenization sanity 检查显示在 `max_length=128` 下零截断。
- OOS 样本中只有一小部分是 Soft-Near 边界样本，大多数是明显 outlier。
- Router 和 Expert 单点能力都不弱，系统主要损耗集中在 Gate 与级联决策。

## 6. 读者应该如何理解这个项目

如果你第一次接触这个仓库，可以按下面的逻辑理解：

1. 先看数据版本，确认什么是 `data/current`。
2. 再看项目分层，理解为什么有 Gate、Router、Expert。
3. 然后看训练与评估流程，知道每一层如何产出结果。
4. 再看性能基线，理解当前强项和瓶颈。
5. 最后看消融实验方案，知道下一步应该验证什么。

## 7. 约束条件

- 训练与调参必须严格 train/val/test 隔离。
- 测试集不用于阈值拟合。
- 输出目录与迁移记录必须可追溯。
- 当前环境优先 CPU 稳定执行，避免受本机 GPU 兼容问题干扰。
