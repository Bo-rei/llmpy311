# 工具入口索引

## 1. 主入口

- `tools/analysis/run_multi_dataset_training_v19.py`：多数据集多KIR训练主入口（支持 `--resume` 与分阶段补跑）。
- `tools/eval/eval_system_pipeline_v19.py`：系统级评估主入口。
- `tools/analysis/run_structure_backbone_ablation_v19.py`：主消融入口。
- `tools/analysis/validate_router_confidence_threshold_v19.py`：Router 阈值校准入口。
- `tools/analysis/run_prototype_gate_frozen_baseline_v19.py`：历史 prototype 最佳结果冻结复现入口。
- `tools/analysis/validate_historical_best_chain_v19.py`：历史最佳链路的来源与路径核验入口。
- `python -m tools.experiments.cluster_separability`：MiniLM 多簇/OOS 实验统一入口；
- `python -m tools.experiments.cluster_separability v20-analysis`：读取 v19 产物，生成 v20 的 K 选择可靠性、near-OOS 方法比较和效率汇总；
- `python -m tools.experiments.cluster_separability v20-random`：运行 KMeans 与随机分簇的受控对照，输出到独立 v20 目录；
- `python -m tools.experiments.cluster_separability v20-end-to-end`：生成 36 个 Gate 替换单元的 preflight 和可恢复命令清单；
- `python -m tools.experiments.cluster_separability v20-adaptive`：运行 Known-train-only silhouette 自适应局部边界 Baseline；
- `python tools/analysis/export_cluster_separability_figures_v19.py`：只读取已冻结 CSV，导出 K 消融、Baseline、near/far 和碎片化聚合图；
  `grid`、`baseline`、`analyze`、`export` 分别负责主网格、受控基线、几何分析和论文导出。
- `tools/compat/textoir/audit_textoir_protocol.py`：独立 TextOIR 仓库、方法注册和 split hash 审计入口。

## 4. v21 MiniLM 假设验证

v21 独立读取 v19 embedding cache，不覆盖 v19/v20：

```bash
python -m tools.experiments.cluster_separability v21-semantic-probe
python -m tools.experiments.cluster_separability v21-casebook
python -m tools.experiments.cluster_separability v21-adaptation --preflight
python -m tools.experiments.cluster_separability v21-adaptation --execute --formal --dataset clinc150 --seed 42 --epochs 1 --batch-size 64
```

`v21-adaptation --formal` 使用完整 train/val/test；默认 smoke 仅验证训练、Gate
评分和产物链，不能作为论文趋势。中间层表示必须重新编码；若 cache 没有
layer2/4/6 hidden states，`layer_preflight.json` 会明确阻断。

## 2. 辅助分析

- `tools/analysis/summarize_ablation_results_v19.py`：主消融结果汇总。
- `tools/analysis/export_ablation_table_v19.py`：论文表格导出。
- `tools/experiments/cluster_separability/`：本轮多簇/OOS 研究的纵向包；
  `protocol.py` 只定义共享指标语义，其余模块不应各自复制 OOS 指标或选择规则。
  `export` 阶段同时生成 K-vs-K1 配对 bootstrap CI、Baseline-vs-selected-K
  配对效应、全网格聚类质量汇总和代表 intent 案例，不需要重跑 embedding。
- `tools/analysis/s2c_code_inventory_v19.py`：源码职责与生命周期盘点。

## 3. 已归档入口

- 历史入口不在当前推荐清单中。需要复现实验时，先从对应输出的 manifest 或 `docs/historical_repro_bundle/` 追溯，而不是猜测归档脚本路径。

## 3. 脚本治理提示

- 新增通用分析入口优先放 `tools/analysis/` 或 `tools/eval/`；同一研究问题的多个阶段优先收拢为 `tools/experiments/<study>/` 纵向包。
- 历史版本不能与主入口混用；新增归档前先记录可追溯的来源和用途。
- 若入口开始承担多个实验形态，应拆成 wrapper + 单一职责子脚本。
- 多数据集训练请统一使用 `dataset_slug` 目录输出（`clinc150`/`banking77_oos`/`snips`），避免混用历史大写命名目录。
