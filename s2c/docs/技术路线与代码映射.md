## 一、系统总体架构

```
输入文本
    │
    ▼
┌─────────────────────────────────┐
│  Stage 0: Gate（开放域检测/OOS） │  ← all-MiniLM-L6-v2 编码 + 多超球检测
│  判断：ID（域内）还是 OOS（域外）│
└──────────────┬──────────────────┘
               │ ID 样本继续
               ▼
┌─────────────────────────────────┐
│  Stage 0.5: Semantic Verifier   │  ← 可选，仅对"不确定区间"样本生效
│  SmolLM-135M 原型匹配 + LLM验证 │
└──────────────┬──────────────────┘
               │ 确认 ID 后继续
               ▼
┌─────────────────────────────────┐
│  Stage 1: Router（域路由）       │  ← SmolLM-135M + LoRA，10 域分类
│  输出：样本属于哪个域（domain）   │
└──────────────┬──────────────────┘
               │
               ▼
┌─────────────────────────────────┐

│  输出：具体意图标签               │
└─────────────────────────────────┘
```

## 二、Stage 0：Gate — 开放域检测（OOS Detection）

### 2.1 技术原理

Gate 的核心思想是：用一个轻量编码器将文本映射到向量空间，然后用**多超球覆盖**（Union-of-Hyperspheres）来刻画"已知意图"的分布边界。

1. **编码**：用 `all-MiniLM-L6-v2`（22M 参数，384 维）将文本编码为向量，冻结不训练。
2. **聚类**：对每个已知意图的训练样本，用 K-means 生成 $K=2$ 个子中心（sub-centroids），中心模式为 `class_centroid_mixture`。
3. **半径计算**：每个子中心对应一个超球，半径用 `mean + λ × std` 方法计算，在验证集上调优 λ。
4. **距离度量**：采用对角马氏距离（diagonal Mahalanobis）。每个局部簇只用分配到该簇的 Known train embeddings 独立估计对角协方差，正则化常数 ε=10⁻⁶；不是全局共享协方差。
5. **决策规则**：样本到最近超球心的距离 ≤ 该球半径 → ID（域内），否则 → OOS（域外）。

| subcenters_per_intent | 2 | 每个意图 2 个子中心 |

## 三、Stage 0.5：Semantic Verifier — 语义验证（可选）

### 3.1 技术原理

Gate 输出的"不确定区间"样本（score ∈ [0.98, 1.05]），由语义验证器做二次判定：

1. **原型匹配**：在 SmolLM-135M 的隐藏层空间中，为每个意图构建原型（K-means 中心）。对不确定样本，计算与所有意图原型的余弦相似度，取 Top-K 候选。
2. **LLM 重排序**：将查询文本和 Top-K 候选意图构造为 prompt，用 SmolLM-135M 解码器的 yes/no 下一个 token 概率作为语义匹配分数。
3. **决策**：语义分数 ≥ 阈值 → ID，否则 → OOS。

### 3.2 最优超参数

| semantic_top_k | 3 |
| prompt_version | ranking_v1 |
| prototype_centers_default | 5 |
| verifier LoRA r | 32 |
| verifier LoRA alpha | 64 |
| batch_size | 16 |
| epochs | 6 |

## 四、Stage 1：Router — 域路由

### 4.1 技术原理

对 Gate 判定为 ID 的样本，Router 将其分类到 10 个语义域（如 banking、travel、home 等）。

1. **模型**：SmolLM-135M（135M 参数）+ LoRA 适配器。
2. **架构**：`SmolLMRouter` = 冻结骨干 + LoRA（rank=32, alpha=64）+ 线性分类头。
3. **编码**：Mean pooling（考虑 attention mask），取最后一层隐藏状态的加权平均。
4. **损失**：CrossEntropyLoss。
5. **优化**：AdamW (lr=2e-4, weight_decay=0.01)，cosine schedule + 10% warmup，梯度裁剪 1.0。
6. **早停**：验证集准确率，patience=5。

## 五、Stage 2：Expert — 细粒度意图分类

### 5.1 技术原理

每个域有独立的 Expert 模型，负责在域内做细粒度意图分类（如 banking 域内 8 个意图）。

1. **模型**：复用 `SmolLMRouter` 架构（SmolLM-135M + LoRA + 分类头），但 LoRA rank 更小。
2. **关键区别**：Router 用 LoRA r=32，Expert 用 LoRA r=16（参数更少，防止小数据集过拟合）。
3. **训练**：每个域独立训练，逐域顺序执行，GPU 内存完全释放后训练下一个域。
4. **推理时**：根据 Router 输出的域名，按需加载对应 Expert 的 checkpoint（lazy loading）。

## 六、推理流程：predict_batch()

### 6.1 完整推理链路

```python
# 入口：src/pipeline/system_pipeline.py → HiLSAMoEV19Pipeline.predict_batch()

def predict_batch(texts):
    # Step 1: Gate 编码 + 多超球判定
    gate_out = _gate_predict(texts)          # → pred(0/1), score, distance

    # Step 2: Semantic Verifier（可选，仅不确定区间）
    if semantic_gate_enabled:
        uncertain = filter(score ∈ [0.98, 1.05])
        semantic_out = smollm_semantic_gate_verify(uncertain)
        # 原型匹配 + LLM 重排序 → 更新 final_gate_pred

    # Step 3: 过滤 OOS，仅 ID 样本继续
    known = filter(gate_pred == 0)

    # Step 4: Router 域分类
    router_out = _router_predict(known)      # → domain_id, domain_prob

    # Step 5: 按域分组 → Expert 意图分类
    for domain, group in groupby(known, key=domain):
        expert_out = _expert_predict_group(domain, group)  # → intent

    return results
```

## 十、关键设计决策

1. **为什么 Gate 用 MiniLM 而不是 SmolLM？**
   Gate 只需要编码→算距离，不需要生成能力。MiniLM-L6-v2（22M）比 SmolLM-135M 小 6 倍，推理速度快，且 sentence-transformers 生态成熟。

2. **为什么 Router 和 Expert 共享架构但 LoRA rank 不同？**
   Router 在全量域数据上训练（样本多），用 r=32 容量足够。Expert 在单域数据上训练（样本少），用 r=16 防止过拟合。

3. **为什么用多超球而非单球？**
   单球 SVDD 假设所有已知意图分布在一个凸包内。实际数据中不同意图分布分散，多超球（每个意图 2 个子中心）能更紧致地包裹边界。

4. **为什么需要 Semantic Verifier？**
   Gate 的多超球判定有"不确定区间"（距离接近半径的样本）。对这些样本用 SmolLM 做语义级验证，能显著提升 OOS 召回率。

5. **为什么 Expert 按域独立训练而非全局统一？**
   每个域的意图数量和难度不同（如 banking 8 类 vs meta 5 类）。独立训练允许每个 Expert 专注自己的分布，避免跨域干扰。
