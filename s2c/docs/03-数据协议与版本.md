# 数据协议与版本

## 1. 当前官方数据版本

- 活跃版本: `data/v19`
- 统一入口: `data/current -> v19`

所有训练、评估和消融默认都应该从 `data/current` 读取，而不是硬编码历史版本路径。

## 2. v19 协议核心规则

- 已知意图与未知意图严格分离。
- Gate、Router、Expert 使用统一版本数据。
- Train/Val/Test 严格隔离，禁止测试泄漏。
- 阈值拟合只允许在验证集执行，测试集只用于最终报告。
- 所有阶段都必须保留数据版本痕迹和审计结果。

## 3. 数据分层

### 3.1 Gate 数据

Gate 负责 ID/OOS 判别。当前审计显示：

- train: 7500
- val: 3100
- test: 5499

这部分数据的用途是让系统先决定“要不要拒识”。

### 3.2 Router 数据

Router 负责把通过 Gate 的 ID 样本分到对应 domain。当前路由器已训练产物的评估显示其单点能力较强，系统级损失主要不是来自 Router 本体。

### 3.3 Expert 数据

每个 domain 都有独立的 `train/val/test`，典型规模约为：

- train: 800
- val: 160
- test: 240

专家数据是纯域内分类数据，目标是域内意图识别，不承担 OOS 拒识职责。

## 4. 数据审计结论

当前审计给出的关键事实是：

- `train_test_overlap = 0`
- `tokenizer = SmolLM2-1.7B` 在 `max_length=128` 下零截断
- OOS 中 `Soft-Near` 占 9.6%，`Far-OOD` 占 90.4%
- 当前审计同时标记 `intent_mapping_inconsistent = true`，因此任何新实验都应先确认映射口径，再做结果比较

这意味着：数据本身足够干净，项目的主要问题不是“数据根本不可用”，而是“边界样本如何处理”。

## 5. 数据变更管理

任何数据变更必须同步记录：

- 来源、时间、样本量、哈希校验（如有）
- 对应实验 ID
- 影响到的 baseline 与报告路径
- 是否改变了 intent/domain 映射口径
