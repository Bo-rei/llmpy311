# 项目结构重整与职责边界（v19）

## 0. 本轮整理计划与边界（2026-07）

本轮只处理可维护性边界，不改动实验结论或重写研究流水线：

1. 明确工作区与可运行项目的关系：上级 `llmpy311/` 只保留分层资产；唯一主研究代码位于 `s2c/`。
2. Router 只保留在 `src/router/router_model.py`；共享 LoRA 编码器在 `src/models/transformer.py`，Expert 在 `src/models/expert.py`。
3. 活跃项目不再保留 `data/`、`outputs/`、本地模型和原始数据的兼容副本；它们分别位于 workspace 的 `assets/` 与 `artifacts/`。历史证据才进入 `archives/`。

验收标准：`src.models.architecture` 已移除；路由器只能从 `src.router.router_model` 导入。项目入口能区分源码、数据与产物，且活跃工作流只经 `python -m src.cli` 启动。

## 1. 目标

本次重整目标是三件事：
- 让“代码入口、数据输入、实验输出”有唯一主路径。
- 降低 `tools/archive` 对日常实验的耦合。
- 保证文档描述与仓库真实状态一致。

## 2. 当前生效结构（维护口径）

- 代码层：
  - `src/`：可复用核心实现（模型、推理、路由、门控、工具函数）。
    - `src/router/`：Router 的唯一实现位置。
    - `src/models/`：共享编码器、Expert 和 Gate 组件，不再导出 Router。
  - `tools/`：训练/评估/分析入口（唯一可执行主入口层）。
  - `scripts/`：数据准备与一次性辅助脚本（非主实验入口）。

- 数据层：
  - `data/multidataset/v19/<dataset_slug>/<kirXX_seed42>/`：多数据集训练输入。
  - `data/current`：当前活跃版本入口（用于兼容旧流程）。

- 输出层：
  - `outputs/`：实验产物、检查点和论文图表；它是证据层，不是源码层。
  - `figures/`：可直接引用的图表输出。

## 3. 解耦约束

- 训练编排脚本只调用 `tools/` 下稳定入口；历史证据只能作为只读输入。
- 新增 Router 实现只能放在 `src/router/`，`src/models/` 不再复制 Router 代码。
- 唯一公开入口是 `python -m src.cli`；`tools/` 与 `scripts/` 仅提供其内部 workflow 实现。

## 4. 多数据集实验命名规范

- 数据集目录名统一使用：
  - `clinc150`
  - `banking77_oos`
  - `snips`

- KIR目录统一使用两位百分比：
  - `kir25_seed42`
  - `kir50_seed42`
  - `kir75_seed42`

## 5. 结果核验清单

具体产物路径由各实验的 manifest 决定。汇总或比较前必须先验证其来源，不能把组件级指标当作完整 Gate / Router / Expert 流水线结果。

## 6. 维护建议

- 新增实验入口时先在 `docs/10-工具入口索引.md` 注册。
- 新增目录规范时同步更新 `docs/02-代码与目录结构.md`。
- 变更产物路径时，必须同时更新汇总脚本和本文档的核验清单。
- 根目录的模型、`lora/` 历史训练、`s2c_submission/` 快照不参与 `s2c/` 代码重构；需要清退时另行建立可恢复的归档计划。
