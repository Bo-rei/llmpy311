# 项目结构重整与职责边界（v19）

## 0. 本轮整理计划与边界（2026-07）

本轮只处理可维护性边界，不改动 Gate -> Router -> Expert 方法或重写
历史研究流水线：

1. 明确工作区与可运行项目的关系：上级 `llmpy311/` 只保留分层资产；唯一主研究代码位于 `s2c/`。
2. Router 只保留在 `src/router/router_model.py`；共享 LoRA 编码器在 `src/models/transformer.py`，Expert 在 `src/models/expert.py`。
3. 活跃项目不再保留 `data/`、`outputs/`、本地模型和原始数据的兼容副本；它们分别位于 workspace 的 `assets/` 与 `artifacts/`。历史证据才进入 `archives/`。
4. 将原本分散在 `tools/analysis/` 和 `tools/experiments/` 的多簇/OOS 新实验收拢为
   `tools/experiments/cluster_separability/` 纵向包，共享指标语义只在 `protocol.py`
   定义一次。
5. TextOIR 只通过 `tools/compat/textoir/` 的 manifest/prediction 契约交换数据，不直接
   import 外部项目，不将其 Python 3.6 时代的内部结构复制进 `src/`。

验收标准：系统流程经 `python -m src.cli` 启动；单一研究主题经一个薄的
module CLI 启动；数据、源码、产物和外部仓库的边界可由测试和 manifest 验证。

## 1. 目标

本次重整目标是三件事：
- 让“代码入口、数据输入、实验输出”有唯一主路径。
- 降低 `tools/archive` 对日常实验的耦合。
- 保证文档描述与仓库真实状态一致。

## 2. 当前生效结构（维护口径）

- 代码层：
  - `src/`：可复用核心实现（模型、推理、路由、门控、工具函数）。
    - `src/router/`：Router 的唯一实现位置。
    - `src/models/`：共享编码器、Expert 和 Gate 组件，不再导出 Router。
  - `tools/`：训练/评估/分析工作流。
    - `tools/experiments/<study>/`：一个研究问题的 runner、baseline、analysis 和
      exporter 放在同一纵向包内。
    - `tools/compat/<external>/`：外部项目的协议审计、子进程运行和结果导入边界。
  - `scripts/`：数据准备与一次性辅助脚本（非主实验入口）。

- 数据层（位于 workspace，不在 s2c Git 仓库内）：
  - `assets/datasets/s2c/source/`：上游只读数据。
  - `assets/datasets/s2c/prepared/data/multidataset/v19/<dataset_slug>/<kirXX_seedYY>/`：多数据集训练输入。

- 输出层（位于 workspace，不在 s2c Git 仓库内）：
  - `artifacts/s2c/outputs/`：实验产物、检查点、审计和论文表图；它是证据层，不是源码层。
  - 图表必须位于具体实验目录或 paper-results 目录，并由 `figure_manifest.json` 追溯。

## 3. 解耦约束

- 训练编排脚本只调用 `tools/` 下稳定入口；历史证据只能作为只读输入。
- 新增 Router 实现只能放在 `src/router/`，`src/models/` 不再复制 Router 代码。
- 系统级公开入口是 `python -m src.cli`；研究级入口必须是有明确研究主题的
  module CLI，例如 `python -m tools.experiments.cluster_separability`。
- CLI 只负责参数分发；指标、选择规则和产物 schema 不在多个脚本中复制。
- `src/` 不反向依赖 `tools/`；外部仓库不能被当作 s2c 内部 package import。

## 4. 多数据集实验命名规范

- 数据集目录名统一使用：
  - `clinc150`
  - `banking77_oos`
  - `snips`

- KIR目录统一使用两位百分比：
  - `kir25_seed42`
  - `kir50_seed42`
  - `kir75_seed42`

## 5. 结果核验清单

具体产物路径由各实验的 manifest 决定。汇总或比较前必须先验证其来源，不能把组件级指标当作完整 Gate / Router / Expert 流水线结果。

## 6. 维护建议

- 新增实验入口时先在 `docs/10-工具入口索引.md` 注册。
- 先复用已有 protocol/I/O 函数；只有当一个文件出现独立变化理由时才拆分，
  不为了“看起来模块化”增加空抽象。
- 代码注释优先解释协议、数据泄漏风险和非显然决策，不逐行复述语法。
- 新增目录规范时同步更新 `docs/02-代码与目录结构.md`。
- 变更产物路径时，必须同时更新汇总脚本和本文档的核验清单。
- 根目录的模型、`lora/` 历史训练、`s2c_submission/` 快照不参与 `s2c/` 代码重构；需要清退时另行建立可恢复的归档计划。
